# 企业查询动态数据源路由设计

## 目标

把已确认的企业查询顺序固化进 Skill：没有精确主体时先用风鸟发现候选，再用企查查核验；已有公司全称或统一社会信用代码时先用企查查精确核验，再用风鸟补齐缺失字段。

## 路由规则

1. 店铺资质页始终是主体锚定的首要证据，不属于企业数据源先后顺序。
2. 只有店铺名或品牌名，且企查查和风鸟都可用：`风鸟模糊发现 → 企查查精确核验 → 风鸟补缺`。
3. 已有公司全称或统一社会信用代码，且两者都可用：`企查查精确核验 → 风鸟补缺`。
4. 只有一个数据源可用时使用该数据源，并保留“待另一数据源复核”的状态。
5. 冲突时按证据优先级裁决：`平台资质页 > 信用代码一致 > 商标/品牌官网 > 企业名称相似 > 电话邮箱`。电话邮箱不能单独确认主体。

## 实现边界

- 新增纯 Python 路由函数和 CLI，只生成查询计划，不持有或调用任何密钥。
- Skill 文档、工作流和工作簿复用说明引用同一套规则。
- 多候选仍保持 `selected: false`，不因某个平台先返回而自动选中。
